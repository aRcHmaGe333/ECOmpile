# Intent Operating Philosophy

## System Contract

ECOmpile exists to give people executable options that improve outcomes.

Role split:

1. Builder role: provide modular, applicable, compatible options.
2. User role: adopt, amend, merge, approve, or discard through real use.
3. System role: detect convergence and compile stable outcomes.
4. Safety role: require explicit final activation decisions.

## Governing Principles

1. Outcomes over rhetoric.
Only keep what holds under repeated real usage.

2. Users as core intelligence.
Convergence is driven by adoption and amendment behavior, not isolated model confidence.

3. Determinism where earned.
When intent and context are known and validated, execute directly.

4. Transparency by design.
Kernels and routing behavior must be inspectable, explainable, and bounded.

5. Low-labor human control.
Automate collection, extraction, clustering, and grouping; reserve human effort for final decisive judgment.

6. Public-safe default.
Expose useful artifacts publicly while keeping sensitive evidence internal.

7. Requirement fidelity by contract.
Each stage must honor explicit schemas and fail on invalid records.

8. Deterministic methods where sufficient.
Use direct deterministic execution when convergence and context match are established.

## Execution Instructions

1. Capture accepted and amended outcomes from authentic interaction traces.
2. Normalize into comparable units and preserve provenance anchors.
3. Mine recurrence, acceptance, reuse, and determinism signals.
4. Group similar candidates into a single dilemma whenever feasible.
5. Require one explicit human decision per dilemma before activation.
6. Route future matches to active kernels; return explicit fallback on misses.
7. Re-score continuously as new usage evidence appears.

## What This Prevents

1. Re-deriving already-solved tasks.
2. High-cost repetition of known-good outputs.
3. Hidden deterministic behavior without review.
4. Manual overload from reviewing near-duplicate candidates one by one.
